答题结构（照这个顺序说，不容易乱）：
① 一句话给结论（10 秒）→ ② 用生活类比解释「为什么」（20 秒）→ ③ 补一个具体数字/名词显深度 → ④ 主动说出局限或坑，显得真做过。
千万别：一上来背公式、说"大概是这样"、或者只讲优点不讲代价。面试官最常砍的就是"你真跑过吗"。

第一梯队 · 几乎必问（背到能脱口而出）

必问 1注意力机制是什么？Q K V 分别干嘛？
一句话背：注意力就是「按相关性，从所有词里挑信息」：拿 Q 去和每个 K 打分，打分归一化后当权重，把对应的 V 加权求和，得到这个词该关注的结果。
大白话
像在图书馆查资料：Q 是你写在检索单上的问题，K 是每本书书脊上的标签，V 是书里真正的内容。先拿问题去跟所有标签比对相似度（Q·K），相似度高的书多读几遍、低的略过，最后把读到的内容按权重混合成一份摘要。所以「词」不再是死的一个向量，而是会根据上下文动态变成"它此刻该关注的东西"。
补深度
公式是 softmax(QKᵀ/√d_k)·V。除以 √d_k 是关键：向量维度大时点积数值会很大，softmax 会被推到饱和区、梯度几乎为零，除一下把方差拉回 1，训练才稳。多头 则是开好几组 QKV 并行看不同关系（一组管指代、一组管句法、一组管位置），最后拼起来再投影一次。
追问
「为什么要多头？」→ 单头只有一种相似度尺度，容易把所有信息平均掉；多头相当于多个子空间并行，参数量基本不变（把 d_model 切成 h 份）。
「self-attention 和 cross-attention 区别？」→ Q 来自自己、KV 也来自自己就是 self；Q 来自解码端、KV 来自编码器输出就是 cross（翻译/多模态对齐用）。
别说错：别把 K 说成"键=答案"，V 才是被取走的信息；也别漏掉 √d_k，一漏面试官就知道是背的。复杂度 O(n²) 要说出来，这是长上下文所有优化的动机。
必问 2为什么需要位置编码？
一句话背：因为自注意力本身「不认识顺序」——把一句话打乱，注意力算出来的结果只是跟着换位置，词与词的相关性一模一样。位置编码就是给每个词贴一个"我是第几个"的门牌号。
大白话
注意力像一屋子人同时互相投票，谁也不管谁坐哪。但"狗咬人"和"人咬狗"字面完全一样、意思相反，不告诉模型顺序它就分不出。所以要额外注入位置信息。
补深度
三代方案要能串起来讲：① 绝对正弦余弦（原始 Transformer，PE(pos,2i)=sin(pos/10000^(2i/d))，不用学、能外推一点）；② RoPE 旋转位置编码（现在的主流，作用在 Q/K 上做旋转，两个位置的点积只跟"相对距离"有关，LLaMA / ChatGLM / Qwen 都用它）；③ ALiBi（不改向量，直接在注意力分数上按距离减一个惩罚）。长上下文外推靠 NTK-aware 缩放、YaRN、位置插值 PI。
追问
「RoPE 为什么好？」→ 相对位置天然内积表达、无需训练参数、可配合缩放外推到训练长度之外。「训练 4k 能直接跑 32k 吗？」→ 不能，直接外推会崩，要做位置插值或在长文本上继续训练。
别说错：别只答"加个位置向量"就停。要主动说"自注意力是置换等变的"这个根因，以及绝对 vs 相对的区别——这是分水岭。
必问 3预训练和微调有什么区别？
一句话背：预训练是"海量无标注文本上做下一个词预测，学通用语言知识"；微调是"少量高质量指令数据上，教它按人的要求好好回答"。前者拼算力拼数据，后者拼数据质量和对齐。
补深度
完整链条讲出来更值钱：预训练（TB 级语料、自监督、几千张卡、学知识）→ SFT 指令微调（几万条 instruction-response 对，学格式和任务）→ 对齐（RLHF / DPO，学人类偏好、少幻觉、拒答）。你简历上写"QLoRA 微调"指的是中间那一环。
追问
「微调会不会把原来学的忘了？」→ 会，叫灾难性遗忘；缓解靠小学习率、少量 epoch、混入通用数据回放、以及 LoRA 这种冻结基座的做法（天然更不容易忘）。
「什么情况不用微调？」→ 只是缺知识用 RAG，只是要格式用 prompt/few-shot，别动不动就微调。
别说错：别说"微调就是继续预训练"。目标函数虽然都是 next-token loss，但数据分布、量级、目的完全不同。
必问 4QLoRA 原理？为什么省显存？
一句话背：LoRA 是「冻结原模型，只在旁边挂一对小矩阵学增量」；QLoRA 再进一步，把冻结的基座压成 4-bit，省的就主要是 权重本身 + 梯度和优化器状态 这三块。
大白话
全量微调像把一本百科全书重印一遍，还得给每一页都备一份修改草稿；LoRA 是原书一个字不动，只夹一张薄薄的勘误表（ΔW = B·A，r 通常 8~64，参数量不到原模型 1%）；QLoRA 再把原书缩印成口袋本（4-bit NF4），桌子一下就够放了。
显存开销7B 全量微调（fp16 + Adam）7B QLoRA
模型权重约 14 GB约 3.5~4 GB（4-bit）
梯度约 14 GB只有 adapter，几十 MB
优化器状态约 28 GB（fp32 主权重+m+v）只有 adapter，几百 MB
合计（不含激活）56 GB 以上，单卡做不了约 8~12 GB，消费级 24G 卡可跑
三个黑话
NF4：针对正态分布权重设计的 4-bit 量化类型；双重量化：连量化用的缩放常数也再量化一次；Paged Optimizer：显存峰值时把优化器状态临时挪到内存，防止 OOM 崩掉。加上梯度检查点，就能单卡微调几十 B 的模型。
追问
「r 怎么选？」→ 小数据集 r=8/16 够用，任务复杂可到 64；r 越大越容易过拟合。
「推理会变慢吗？」→ 不会，把 BA 合并回 W 即可，零额外延迟（这点很加分）。
「缺点？」→ 量化有精度损失；多任务/大域偏移时不如全量；adapter 切换要管理。
别说错：别只说"因为参数少"。真正的大头是不存全量梯度和 Adam 状态（Adam 每个参数要额外存 2 份动量 + fp32 主权重）。这句说出来，面试官会认为你真跑过。
必问 5vLLM 为什么推理快？
一句话背：两个核心：PagedAttention 把 KV Cache 像操作系统管内存一样分页，消灭显存浪费；连续批处理 让请求随到随走，GPU 不用等最慢那个生成完。
大白话
生成时每个已算过的 token 的 K/V 要缓存（KV Cache），否则每生成一个字都得把前面全重算一遍。老做法是给每个请求按"最大长度"预留一整块连续显存，像给每人预留一整排座位，实际只坐了几个 → 论文里测出 60%~80% 的显存被浪费。PagedAttention 把缓存切成固定小块按需分配，浪费降到 4% 以下，同样显存能同时服务几倍请求。
连续批处理则像电梯不等满员：谁到了谁先上、谁到了楼层就下，马上补新人，而不是一批人全到齐才发车。
补深度
再补就有区分度了：前缀缓存（相同 system prompt 复用 KV）、投机解码（小模型起草、大模型一次校验）、KV 量化 / GQA、chunked prefill 把长 prompt 拆块避免阻塞解码。吞吐相对朴素 HuggingFace generate 常有数倍到十几倍提升，但别把倍数说死，取决于批量、长度和卡。
追问
「KV Cache 为什么占显存？」→ 随 序列长度 × 层数 × 头数 × batch 线性增长，长上下文下常比模型权重还大。「prefill 和 decode 区别？」→ prefill 并行算整段 prompt，是算力密集；decode 逐字生成，是访存密集，所以优化手段不同。
别说错：别把 vLLM 说成"模型更快了"——它不改变模型计算量和输出质量，快的是显存管理和服务调度，属于系统层优化。也别把 TensorRT-LLM 和 vLLM 混为一谈。

第二梯队 · 高频，答得出就是加分

高频 6Transformer 整体结构？Encoder / Decoder 区别？
背：每层 = 多头自注意力 + 前馈网络 FFN，各配一个残差连接和 LayerNorm。Encoder 用双向注意力（看全句，适合理解），Decoder 加 causal mask 只能看左边（适合生成）。现在主流大模型（LLaMA、GPT、Qwen、ChatGLM3 之后）都是 Decoder-only。
追问
「为什么 Decoder-only 成主流？」→ 结构简单、参数效率高、训练和推理目标一致、zero-shot 泛化好、容易堆规模。
「残差和 LayerNorm 干嘛？」→ 残差给梯度开高速路，让几十层能训起来；LayerNorm 对单个样本自己归一化，不依赖 batch，变长句子更稳（BatchNorm 在 NLP 上不稳）。LLaMA 用 RMSNorm + Pre-Norm，训练更稳更省。
「FFN 里是什么？」→ 升维→激活→降维，LLaMA 用 SwiGLU 替代 ReLU。
高频 7LLaMA 和 GLM / ChatGLM 有什么不一样？
背：LLaMA 是 Meta 的 Decoder-only：RoPE + RMSNorm + SwiGLU，Llama 2/3 部分规格还用了 GQA 省 KV 显存。GLM 早期用"自回归填空"目标加 2D 位置编码，偏理解+生成混合；ChatGLM3 / GLM-4 之后也基本回到 Decoder-only 路线。工程上最大差别其实是中文语料与国内生态、开源协议、以及能不能顺利拿到权重。
追问
「GQA/MQA 是什么？」→ 多个 Query 头共享一组 K/V 头，KV Cache 直接缩小几倍，推理更快，质量损失很小。
「选型怎么考虑？」→ 显存预算、中文能力、许可证、社区工具链（vLLM/PEFT 支持是否成熟）、能不能本地下载。
高频 8指令数据怎么做清洗？
背：六件事：去重、去噪、去隐私、过滤长度与语言、格式统一、质量打分筛选。核心原则是数据质量 > 数据数量，几千条干净数据往往胜过几十万条脏数据。
具体做法
去重（MinHash / SimHash / 精确哈希，防重复样本让模型背答案）；乱码、HTML 标签、广告、截断样本过滤；手机号身份证等 PII 正则剔除；按 token 长度截断或丢弃（超出 max_len 的会拖慢训练）；统一成 {"instruction", "input", "output"} 或 chat template，务必和推理时的模板一致；用规则或小模型打分去掉低质问答；最关键：切分前先去重，防止训练集污染测试集。
追问
「数据不平衡怎么办？」→ 按任务类型配比采样、过采样稀缺类、加通用数据回放防遗忘。「怎么判断清洗有效？」→ 小样本先训一版看 loss 曲线和抽样输出，比空谈指标靠谱。
高频 9微调完怎么评估效果？
背：分三层：① 自动指标（留出集 loss / PPL、任务准确率、EM/F1，分类任务直接看准确率）→ ② 生成质量（人工盲评或 LLM-as-judge 打分、A/B pairwise 胜率、幻觉率、拒答率、格式遵循率）→ ③ 回归检查（通用能力有没有退化、有没有灾难性遗忘、安全性）。
关键判断
loss 降了不等于回答变好，PPL 只反映续写概率，不反映有用性、安全性和指令遵循。所以一定要有一份人工写的、模型没见过的、覆盖边界情况的评测集，并固定 temperature/seed 保证可复现。
追问
「LLM 打分可信吗？」→ 有位置偏见、偏爱长答案、自偏好，需随机交换顺序、多条采样、抽一部分人工校准。
「BLEU/ROUGE 能用吗？」→ 开放式生成参考价值有限，只适合翻译/摘要这类有确定参考文本的任务。
高频 10分布式训练怎么做的？
背：按"切什么"记：数据并行 DDP（每卡一份完整模型，分数据，反向后 all-reduce 同步梯度）→ ZeRO（把优化器状态 / 梯度 / 参数依次切分到各卡，DeepSpeed 1/2/3，显存换通信）→ 模型装不下再上 张量并行（层内切矩阵，要 NVLink 高带宽）和 流水线并行（按层切，有 bubble 气泡）。三者叠加叫 3D 并行。
省钱三招
混合精度（bf16 比 fp16 不易溢出、不用 loss scaling）、梯度检查点（用重算换显存）、梯度累积（小 batch 攒几步再更新，模拟大 batch）。
追问
「DDP 和 DP 区别？」→ DP 单进程多线程、主卡瓶颈、GIL；DDP 多进程 ring-allreduce，扩展性更好。
「通信成为瓶颈怎么办？」→ 梯度桶合并、重叠通信与计算、增大 batch、换更高带宽互联。
高频 11HuggingFace 生态你用了哪些？
背：transformers（模型/Trainer）、datasets（加载与流式处理）、tokenizers（分词）、peft（LoRA/QLoRA）、trl（SFTTrainer/DPO）、accelerate（分布式一行配置）、bitsandbytes（4-bit 量化）、evaluate（指标）。
加分细节
能说出真实踩过的坑最值钱：chat template 与训练格式不一致导致回答错乱；pad_token 未设置导致 loss 异常；padding 侧与 FlashAttention 冲突；label 里 prompt 部分要 mask 成 -100（只对回答算 loss）；国内下载慢用镜像或 snapshot_download 断点续传。
高频 12多模态 CLIP / LLaVA 大概怎么做？
背：CLIP 用对比学习把图片和文字压到同一个向量空间（配对的相似度拉近、不配对拉远），所以能零样本分类。LLaVA = CLIP 视觉编码器 + 一个投影层 + 大语言模型，把图像特征当成"视觉 token"喂给 LLM；训练一般两阶段：先用图文对只训投影层做对齐，再用视觉指令数据做端到端微调。
追问
「投影层为什么重要？」→ 视觉特征和文本嵌入空间不同，不对齐 LLM 看不懂；从线性层到 MLP 效果有明显提升。「难点？」→ 高分辨率图片的 token 数爆炸、细粒度 OCR/空间定位弱、幻觉。

第三梯队 · 一句话也要能接住

问题一句话答案
为什么会有幻觉？模型学的是"最可能的续写"不是"事实"，加上训练数据错误/过时、解码随机性；缓解靠 RAG、对齐、事实校验、降低温度，不能根治。
temperature / top-p 干嘛？控制采样随机性：temperature 调整分布陡峭程度，top-p 只在累积概率前 p 的候选里采样；越高越发散、越低越保守。
生成重复怎么治？repetition penalty、no_repeat_ngram、提高 top-p、检查训练数据里的重复样本和 EOS 是否缺失。
Tokenizer 用哪种？BPE / BBPE / SentencePiece；中文按字或子词切，直接影响 token 数、成本和长度外推。
显存不够怎么办？QLoRA 量化、梯度检查点、梯度累积、缩短 max_len、ZeRO-3 + CPU offload、换更小基座。
loss 不降 / 炸了？先查学习率（LoRA 常用 1e-4~2e-4）、数据格式与 label mask、混合精度溢出、脏数据；再降 lr、warmup、梯度裁剪。
过拟合怎么看？训练 loss 降但验证 loss 升、回答开始背训练集；减 epoch、加数据多样性、调小 r、加正则/早停。
TensorRT-LLM 和 vLLM？都在做推理加速；vLLM 主打分页 KV + 连续批处理、易上手生态好；TRT-LLM 是 NVIDIA 的编译优化路线，极致性能但适配成本高。

最容易被砍的一关：「你真做过吗」

杀手问说说你微调时遇到的坑，怎么解决的？
为什么危险
前面所有概念都能背，唯独这题只能靠真跑过。背答案是过不了这关的，一追问具体数字就露馅。
要准备好
至少能报出这 7 个数/事实：① 基座模型全名与参数量 ② 数据集名称与清洗后条数 ③ 单卡型号与显存峰值 ④ 训练时长 / epoch / loss 从多少降到多少 ⑤ QLoRA 的 r、alpha、lr、4-bit 类型 ⑥ 一个具体失败现象 + 排查过程 ⑦ 微调前后同一个 prompt 的回答对比。
真实高频坑
chat template 对不上 → 回答复读或不终止；没设 pad_token / label 没 mask prompt → loss 下不去；显存峰值 OOM → 开 paged optimizer + 梯度检查点；量化后精度掉 → 换 bf16 计算、关键层不量化；数据没去重 → 评测虚高。
诚实建议：与其多背 20 道八股，不如花半天用 LLaMA-Factory 或 PEFT 官方脚本，在几百条数据上真跑一次 QLoRA，把上面 7 项记成笔记 + 存 2 张对比截图。这既是这关的答案，也是简历上唯一能撑住的项目描述。没跑过就别写"熟练掌握"，写"了解原理、正在复现"更稳。

30 秒自我介绍模板（照着填）

我是通信工程本科，自学转向大模型方向。主要做三件事：① 用 HuggingFace + PEFT，在 [数据集，约 X 条] 上对 [基座模型] 做 QLoRA 指令微调，单卡 [显卡] 显存峰值 [X GB]，完成了数据清洗、训练、评估全流程；② 用 [留出集 / 人工评分 / pairwise 胜率] 做前后对比，[具体指标] 从 X 提升到 Y，并针对 [某个坑] 做了排查；③ 从零实现了多头注意力和 RoPE 位置编码，理解了 [某点]。目前在用 vLLM 做部署优化，代码和实验记录都在 GitHub。
要点
每段都必须带数字或具体名词，别用"熟悉/掌握/深入了解"堆形容词。面试官会顺着你给出的每个数字追问，所以只写你真能答上来的。
用法：先只背第一梯队 5 题的"一句话背"，再逐题补类比和追问；面试前一晚把「杀手问」的 7 个数字过一遍。
提醒：这份手册解决的是"能开口、不被概念题刷掉"。真正拿 offer 靠的是有一次能讲清楚细节的完整实验——概念可以背，细节不能装。
