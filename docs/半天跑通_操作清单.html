半天跑通 QLoRA · 照着敲操作清单

目标不是学代码，是拿到面试那 7 个数字。每步都有「预期看到什么」和「失败了怎么办」。

环境：pytorch-env / Python 3.12.10torch 2.9.1+cu126 RTX 4060 Laptop 8GBCUDA 12.6 · bf16 可用空闲显存 6.88GB

先说清「第一步」到底是什么

第一步 = 验收环境 + 跑通一次最小训练闭环。不是装包、不是下载模型、更不是看代码。目的只有一个：证明这台机器真的能用 GPU 把模型训起来，而不是只在命令行里显示 "cuda available"。
动作做了什么通过标准
① 认环境找到你真正的 Python（pytorch-env），别用系统那个版本号对得上
② 查显卡读型号、显存、CUDA 版本、bf16 支持8GB / 12.6 / True
③ 真算一次在 GPU 上做一次前向 + 反向（不是只查询状态）loss 和梯度有数值
④ 最小训练闭环训练 → 保存 → 重新加载 → 推理loss 降下去、预测对得上
已代跑完成，真实输出：起始 loss 149.8535 → 最终 0.0003；学到 w=2.005（目标 2.0）、b=0.964（目标 1.0）；重新加载后 x=5 推理得 10.990（期望 11.0）。模型已存为 step1_model.pth。
脚本：step1_verify_gpu.py、step1_train_minimal.py（都在 llm-roadmap/）。
这一步对面试的意义：你已经能诚实说「我在本机 GPU 上跑通过完整的训练/保存/推理链路」。但它还不够写进简历——面试官要的是「微调了什么模型、什么数据、效果提升多少」，所以要继续第 2~5 步。

后面四步（半天路线）

2装 QLoRA 依赖约 5~10 分钟
你这环境现在只有 torch + numpy。微调要用到 HuggingFace 全家桶，一次装齐。
# 在任意终端执行（用你自己的环境，别用系统 python）
c:/Users/admin/pytorch-env/Scripts/pip.exe install ^
  transformers datasets peft trl accelerate bitsandbytes ^
  -i https://pypi.tuna.tsinghua.edu.cn/simple

# 验证
c:/Users/admin/pytorch-env/Scripts/python.exe -c "import transformers,peft,bitsandbytes;print('OK')"
Windows 上最容易卡在这：bitsandbytes 是 4-bit 量化的核心，Windows 支持较晚，常见报错是「检测不到 CUDA / FATAL: CUDA Setup」。装不上先别死磕——换 LoRA（不量化）先把链路跑通，1.5B 模型 bf16 本来就装得下 8GB；之后再回头补 QLoRA 这个关键词。两头不耽误。
预期看到：最后一行打印 OK。
3下模型 + 下数据约 10~20 分钟
8GB 显存只能选小模型，别下 7B。首选 Qwen2.5-1.5B-Instruct（约 3GB，中文好、生态全）。数据用公开的少量指令数据即可，几百条就能跑。
# 国内直连 HuggingFace 慢，用镜像或 ModelScope
c:/Users/admin/pytorch-env/Scripts/pip.exe install modelscope -i https://pypi.tuna.tsinghua.edu.cn/simple
c:/Users/admin/pytorch-env/Scripts/python.exe -c "from modelscope import snapshot_download; snapshot_download('qwen/Qwen2.5-1.5B-Instruct')"
为什么不用 GitHub：LLaMA-Factory 那些仓库在 GitHub，你之前提过连不上；ModelScope 是国内源，稳。
数据格式：统一成 {"instruction":"...","input":"","output":"..."}，训练前先去重再切训练集/验证集——面试会问这个。
别说错：简历别写"微调 LLaMA-7B"，8GB 卡跑不动 7B QLoRA（权重 4bit 约 4GB + 激活 + 优化器，很容易 OOM）。写清楚是 1.5B 反而可信，面试官一问显存就对得上。
4跑一次 QLoRA 微调约 1~2 小时
用 peft 官方示例或 LLaMA-Factory 的 yaml 配置，改配置不改代码。关键参数记下来，面试要报：
参数建议值为什么
r / alpha16 / 32r 小数据够用，大了易过拟合
learning rate1e-4 ~ 2e-4LoRA 专用量级，比全量微调大
max_len5128GB 显存下别开 2048
batch1 + 梯度累积 8省显存
精度bf164060 支持，比 fp16 不易溢出
必开gradient checkpointing用重算换显存，防 OOM
预期看到：终端每隔若干步打印 loss，从 2.x 往 1.x 降；跑完生成 adapter 权重文件夹。
最常见的两个坑：① chat template 和训练格式不一致 → 模型复读、不停止；② label 没把 prompt 部分 mask 成 -100 → loss 降不下去。踩到任意一个，记下来，这就是面试「说个你遇到的坑」的答案。
5记录 7 个数字 + 前后对比约 20 分钟
这一步才是「能写进简历」的产出。做一张实验记录表，然后存 2~3 张对比截图。

评估别只报 loss：留 50 条模型没见过的题，同一个 prompt 分别问「微调前 / 微调后」，人工或让大模型打分看谁更好。loss 降 ≠ 回答变好，这句在面试里说出来很加分。
做完这一步，简历就能写：「基于 HuggingFace PEFT，在 RTX 4060 8GB 单卡上使用 QLoRA 对 Qwen2.5-1.5B 进行指令微调，独立完成数据清洗、训练与评估；通过梯度检查点与 bf16 混合精度将显存峰值控制在 6.4GB，在 50 条留出集上人工盲评胜率 62%。」——每个数字你都答得上来，追问答不倒。
顺序不能跳：验收 → 装依赖 → 下模型 → 微调 → 记录。跳到第 4 步最容易因为环境没验好，在报错里耗一整天。
诚实提醒：第 2、3 步的网络与 bitsandbytes 兼容性是 Windows 上真实存在的不确定性，可能要绕路（先 LoRA 后 QLoRA）。这份清单给的是最短路径，不是保证一次成功。
